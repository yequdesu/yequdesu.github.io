二、任务要求的实现

3.1 项目设计与技术栈

本次任务被拆分为以下环节：数据获取、数据预处理、聚类分析、结果输出和数据可视化。

  • 数据获取：通过B站搜索API获取相关视频BV号，然后爬取弹幕XML数据。
  • 数据预处理：清洗弹幕文本，分词，过滤停用词，向量化文本。
  • 聚类分析：使用KMeans算法对向量化的文本进行聚类，生成主题摘要。
  • 结果输出：将统计结果和聚类摘要保存到Excel文件。
  • 数据可视化：生成静态词云图和动态交互式词云。

完成各个环节的渠道和方式：

  • 数据获取：使用requests库调用B站API，解析XML获取弹幕。
  • 预处理：使用jieba分词，sentence-transformers向量化。
  • 聚类：使用sklearn的KMeans。
  • 可视化：wordcloud生成静态图，p5.js生成动态图。

使用的技术栈：

  • Python 3
  • 数据处理：pandas, jieba
  • 向量化：sentence-transformers
  • 聚类：scikit-learn
  • 可视化：wordcloud, matplotlib, p5.js
  • 爬虫：requests, xmltodict
  • 其他：tqdm, argparse

3.2 爬虫与数据处理

业务逻辑：程序首先通过B站搜索API获取关键词（如”大语言模型”）搜索结果前300个视频的BV号，然后逐个获取视频CID和弹幕XML，解析弹幕文本，过滤噪声（如”666”），统计词频前8的弹幕，生成词云，最后进行语义聚类分析，将弹幕分为8个主题。

代码设计包含5个类：DataLoader（数据加载）、Preprocessor（预处理）、ClusterAnalyzer（聚类分析）、OutputHandler（输出处理），以及main.py作为入口。

关键函数说明：

  • get_search_bvids(keyword, max_videos=360)：调用搜索API获取BV号列表。
  • fetch_danmaku(bvid)：通过BV号获取弹幕列表。
  • clean_and_tokenize(danmaku_list)：清洗、分词弹幕文本。
  • vectorize_texts(texts)：使用SentenceTransformer向量化文本。
  • perform_clustering(embeddings, texts)：执行KMeans聚类。
  • generate_cluster_summary(cluster_texts)：生成聚类摘要。

3.3 数据统计接口部分的性能改进

在数据统计接口部分的性能改进上花费了约30分钟。

改进思路：使用pandas的向量化操作代替循环，缓存停用词加载，避免重复网络请求，使用tqdm显示进度减少用户等待焦虑。

程序中消耗最大的函数是vectorize_texts，因为模型加载和编码耗时较长。可以通过批处理和GPU加速进一步优化，但当前使用CPU已满足需求。

3.4 数据结论的可靠性

结论：B站用户对大语言模型应用的主要看法包括应用成本高、潜在应用领域广泛（如教育、创作）、担忧隐私和伦理问题。

通过聚类分析的8个主题数据得出，如主题6”AI模型在视频内容中的应用，探讨人类注意力机制与AI的相似性”，主题7”AI和模型讨论”。

判断方式：基于词频统计和聚类结果的代表关键词，如”成本”、”隐私”、”教育”等高频词。

3.5 数据可视化界面的展示

数据可视化界面包括静态词云图和动态交互式词云。

组件：静态词云使用wordcloud库生成PNG图像，动态词云使用p5.js在HTML中渲染，具有鼠标交互效果。

设计思路：静态词云直接展示词频，动态词云添加物理模拟，让词随鼠标移动，具有吸引力。使用中文字体确保显示正确。

3.6 附加题展示

附加题实现：鼠标可交互的动态词云（index.html）。

功能的实现思路：使用p5.js库加载词云数据JSON，创建词对象数组，每个词具有位置、速度、加速度等物理属性。在draw函数中应用随机力、鼠标斥力和阻尼，更新词位置，实现动态效果。

功能的创新点：词云不仅静态展示，还具有交互性，用户鼠标靠近时词会受斥力影响移动，增加趣味性和参与感。

对于该功能能解决的问题或内容：传统词云静态展示，用户被动观看；动态交互词云让用户主动参与，提升数据可视化的吸引力和用户体验，帮助更好地理解弹幕语义分布。

三、心得体会

项目概述

在本作业中，我完成了弹幕语义聚类项目的开发，包括数据加载、预处理、聚类分析和输出处理等模块。通过代码分析、修改、重构和PSP记录，我对软件工程实践有了更深刻的理解。

代码分析反思

在代码分析阶段，我仔细阅读了项目的各个模块，发现代码结构较为清晰，但存在一些冗余和耦合问题。例如，数据加载模块与预处理模块之间的接口设计不够灵活，导致后续修改时需要调整多个文件。分析过程中，我学习到模块化设计的重要性，以及如何通过抽象接口降低耦合度。

代码修改和重构反思

在修改代码时，我重构了部分函数，将重复逻辑提取为公共方法，提高了代码的可维护性。重构过程中，我遇到了一些挑战，如确保重构后功能不变，这需要编写充分的测试用例。反思来看，重构不仅改善了代码质量，还增强了我的重构技能，使我更加注重代码的简洁性和可读性。

PSP记录反思

PSP（Personal Software Process）记录让我对时间管理有了新认识。在预估阶段，我低估了调试时间，导致实际时间超出预期。通过实际记录，我发现了自己的弱点，如在编码阶段容易陷入细节而忽视整体进度。未来，我会更加重视PSP的使用，将其作为项目管理的工具。

学习到的知识

通过这次作业，我学习到了：

  • Python数据处理库（如pandas、scikit-learn）的实际应用
  • 聚类算法的原理和实现
  • 单元测试的重要性
  • 版本控制（Git）的使用
  • 软件工程的最佳实践，如DRY原则和SOLID原则

遇到的问题

作业过程中遇到的问题包括：

  • 数据格式不一致导致的加载错误，解决方案是通过异常处理和数据验证
  • 聚类算法参数调优困难，通过交叉验证和网格搜索解决
  • 代码性能瓶颈，在大数据量时出现内存不足，通过优化算法和使用生成器解决

未来改进建议

  • 引入更先进的聚类算法，如DBSCAN，以提高聚类效果
  • 增加可视化模块，便于结果展示
  • 完善测试覆盖率，确保代码质量
  • 采用CI/CD流程，自动化测试和部署
  • 加强文档编写，提高项目的可维护性

总体而言，这次作业让我从实践中体会到软件工程的精髓，未来将继续提升自己的技能。
